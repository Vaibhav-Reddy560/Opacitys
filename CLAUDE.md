# Git commit rules (user-specified, overrides default behavior)

- **Never commit without explicit approval.** Even when changes are complete, verified, and the user has been discussing them as "done," do not run `git commit` until the user replies with something like "ok commit" or "yes commit it." Finishing a task is not itself approval to commit — always ask first, then wait for a clear go-ahead.
- **Never include Claude/AI attribution in commits.** No `Co-Authored-By: Claude ...` trailer, no Claude Code icon/link, no mention of Claude or AI authorship anywhere in the commit message. Write commit messages as if the user wrote them.
